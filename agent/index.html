Start with the host, then choose one route

  1. Identify the host repository, its instructions, modality, reward callback, sample grouping, device ownership, and requested scope. Use an existing authorized checkout or retrieve this repository if accessible; an inaccessible repository is missing context, not permission to invent its contents.
  2. Read the reward contract. Inspect the exact source symbols linked from the code map before editing a host integration.
  3. Load only the skill and HTML workflow needed for the request. Add the memory route only when cross-run calibration is part of the task.
  4. Run the offline source audit, adapt the host reward seam, and use the verification ladder. Deliver an HTML handoff with evidence and explicit unrun checks.

Design to preserve

Plan / Act / Reflect
Ground emotional intent, observe heterogeneous evidence, then calibrate trust for the current video. Act evaluates an already generated video; it does not generate it.
RewardMemory / Evolve
A completed run supplies reliability evidence for bounded weight multipliers used in a later run. The released training route reads a fixed table; it does not update reward-model parameters or write back online.
Unavailable evidence
Validity and activity determine fusion support. A neutral score such as 0.5 does not establish provider availability.
Scope of transfer
The released scorer consumes video paths. An image, tensor-native, asynchronous service, or other modality needs an explicit adapter and validation; the research transfer claim is not a universal runtime API.

Offline source audit

python3 agent/tools/audit.py --output /tmp/emoreward-audit.html

The standard-library audit checks source identity, symbols, HTML routes, and the seven-provider contract. It imports no model, downloads no weights, and does not establish scoring quality or host integration success. If source hashes drift, inspect the changes and update this kit's manifest only after reconciling its guidance.
